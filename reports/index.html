01 / Résultats mesurés

Trois modèles, un même test

Autre réglage : privilégier les faibles fausses alertes

02 / Méthode

Une séparation par captures sources

train16 captures
validation11 captures
test14 captures
unlabeled4 captures
  1. Lecture des 45 captures brutes directement dans l'archive vérifiée ; suppression de l'identifiant d'anonymisation FFF, pas d'échantillonnage des messages.
  2. Fenêtres temporelles disjointes de 0,5 seconde : fréquence par identifiant, temps intermessages et statistiques des huit octets de données. Les fenêtres sans message ne sont pas créées.
  3. Vocabulaire d'identifiants appris sur les captures normales d'entraînement. Les identifiants nouveaux sont regroupés dans une proportion explicite.
  4. Robust profile et Isolation Forest ajustés sur le trafic normal uniquement. Random Forest entraînée sur les captures normales et les premières répétitions d'attaques.
  5. Seuils réglés sur la validation. Troisièmes répétitions et attaque coolant gardées au test. Variantes fabrication / masquerade toujours dans le même lot.

Le profil robuste mesure les écarts aux plages normales ; Isolation Forest recherche des observations atypiques ; Random Forest apprend une classification avec les labels disponibles. Aucun nom de capture, label, instant absolu ou paramètre d'injection n'entre dans les caractéristiques.

Protocole complémentaire sans attaques d'apprentissage

Les deux modèles non supervisés sont aussi évalués sur toutes les captures d'injection et le trafic normal du test, avec un seuil calibré sur les seules captures normales de validation. Aucun label d'attaque ne sert à choisir ce seuil. Les variantes restent corrélées : ce protocole n'est pas une preuve de généralisation à un autre véhicule.

03 / Inspection

Voir le comportement dans le temps

Le score est disponible à la fin d'une fenêtre. Toute estimation de délai à partir du début de fenêtre est discrétisée et doit ajouter le temps d'attente de la fenêtre et de calcul.

Les importances par impureté décrivent le modèle et sont biaisées vers certaines variables ; elles ne constituent pas une explication causale.

05 / Lecture critique

Ce que ces résultats permettent d'affirmer

  • Les performances concernent des fenêtres de captures ROAD d'un seul véhicule ; aucune validation multi-véhicule ou sur véhicule réel n'est revendiquée.
  • Les labels reconstruits par intervalle, identifiant et données peuvent confondre une trame légitime et une injection identique. La fenêtre est positive dès qu'un message correspond.
  • Les quatre captures accelerator, sans labels d'injection exploitables, sont exclues des métriques binaires. Leur taux d'alerte est enregistré séparément dans le manifeste.
  • Les captures présentent un déséquilibre important entre trafic normal et attaques. Le F1 et la PR-AUC dépendent de cette prévalence.
  • Les calculs de débit portent sur les caractéristiques déjà extraites. Ce traitement hors ligne n'est pas un benchmark temps réel embarqué.
  • Les captures vides et les périodes sans message ne produisent pas de fenêtres : la détection d'une disparition complète du trafic est hors périmètre.
  • Les mesures can-train-and-test sont présentées dans un rapport complémentaire distinct ; elles ne sont pas mélangées aux résultats ROAD.
